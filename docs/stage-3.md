# Этап 3. Разбор скриншота

Снимок читается на этом компьютере. Распознанный текст можно исправить, и только после этого он идёт в уже подключённую модель `tfidf-linearsvm-0001m`. Второй классификатор мошенничества не создавался. Модель не переобучалась.

## Почему Apple Vision

На этом Mac 22 ноября 2026 проверены два локальных варианта.

| | Apple Vision | Tesseract |
| --- | --- | --- |
| Установлен | Да, в системе. Swift 6.0.2, `arm64-apple-macosx15.0` | Нет |
| Русский | `ru-RU` в `supportedRecognitionLanguages()` | Пакет `rus` пришлось бы ставить отдельно |
| Казахский | Нет в списке языков | Пакет `kaz` тоже не установлен |
| Сеть и оплата | Не нужны | Не нужны, но нужна установка |
| Память | Системный фреймворк, отдельная модель не скачивается | Отдельные языковые данные |

Другие облачные OCR не рассматривались: снимок не должен уходить наружу.

Vision читает русский и английский. Казахский он не поддерживает. На синтетическом снимке казахские буквы `ә ғ қ ң ө ұ ү һ і` были подменены похожими русскими, поэтому сам факт чтения кириллицы не означает поддержку казахского.

## Как устроен разбор

1. Браузер отправляет файл на `POST /api/v1/analysis/screenshot`.
2. API проверяет размер до 8 МБ и сигнатуру PNG, JPEG или WEBP. Расширение файла не считается доказательством формата.
3. Байты уходят в локальную программу `vision_ocr` через стандартный ввод. Файл на диск не пишется.
4. Программа читает ширину и высоту из заголовка. Сторона больше 8000 пикселей или больше 12 000 000 пикселей отклоняется до полного разбора.
5. Картинка уменьшается до 2400 пикселей по длинной стороне, с учётом поворота из снимка. Координаты и служебные поля снимка в ответ не попадают.
6. `VNRecognizeTextRequest` работает в точном режиме с языками `ru-RU` и `en-US`. Строки сортируются сверху вниз.
7. Пустой результат возвращает `no_text` и пустую строку. Текст не дописывается.
8. Человек правит поле и нажимает проверку. Дальше вызывается прежний `POST /api/v1/analysis/text`.

Ссылки на снимке не открываются. Команды из распознанного текста не выполняются.

## API

`POST /api/v1/analysis/screenshot`, поле формы `upload`.

Успех:

```json
{
  "status": "ok",
  "text": "распознанные строки",
  "engine": "apple_vision",
  "warnings": ["kazakh_ocr_unsupported"],
  "line_count": 1
}
```

`status: no_text` означает, что читаемого текста нет. Это не оценка безопасности.

Ошибки не содержат снимок и распознанный текст:

| Код | HTTP | Когда |
| --- | --- | --- |
| `payload_too_large` | 413 | Больше 8 МБ |
| `unsupported_type` | 415 | Не PNG, JPEG или WEBP |
| `unreadable` | 422 | Файл повреждён |
| `too_many_pixels` | 422 | Слишком большое разрешение |
| `ocr_timeout` | 408 | Дольше 20 секунд |
| `ocr_not_available` | 503 | Нет Swift или Vision |

Обычный текст по-прежнему ограничен 48 КБ. Для снимка предел тела запроса — 8 МБ плюс 64 КБ на поля формы. Количество POST по-прежнему ограничено лимитом процесса.

## Что происходит с текстом и снимком

- Снимок не пишется в MySQL и не сохраняется на диск.
- Временный файл не создаётся: байты живут в памяти процесса и в дочерней программе до конца распознавания.
- Ответ не возвращает EXIF, GPS и комментарии файла. На проверке комментарий `SECRET-LOCATION` внутри PNG в ответ не попал.
- Распознанный текст не пишется в журнал. Журнал по-прежнему получает тип ошибки и путь.
- Исходное сообщение по-прежнему не сохраняется. Запись в `analysis_records` этот этап не добавляет.
- Готовые снимки тестов в Git не входят. Тест рисует их в памяти.

## Ограничения распознавания

Проверка 22 ноября 2026 на синтетических PNG с Arial Unicode, 42 пункта, белый фон. Это не качество на фотографиях экрана телефона.

| Снимок | Что вернул OCR |
| --- | --- |
| Русская просьба перевести деньги | Строка прочитана полностью, предупреждений уверенности нет |
| Русская бытовая фраза | Прочитана полностью |
| «Не сообщайте никому код из SMS» | Прочитана полностью |
| Две строки | Сохранён перевод строки, `line_count` равен 2 |
| Пустой белый снимок | `no_text`, пустая строка |
| Круг без букв | Пустая строка |
| Сильное размытие той же русской просьбы | `no_text`, текст не восстановлен |
| Казахская фраза | Прочитана с подменой букв: `Сэлеметсіз бе, шутыл турде акшаны аударыныз`. Есть `low_ocr_confidence` |
| Смешанная фраза | Русская часть верна, казахская подменена: `акшаны аударыныз` |

Каждый ответ содержит `kazakh_ocr_unsupported`. Если распознавание неуверенное, интерфейс ставит язык «не указан», чтобы не выдавать подменённый казахский текст за проверенный русский. Если в тексте всё же остались казахские буквы, язык ставится казахским.

## Ограничения модели

Модель та же, `tfidf-linearsvm-0001m`. Её русский синтетический macro-F1 0.842 не описывает живую переписку и не описывает качество OCR.

- Низкий риск показывает рекомендацию, что это не гарантия безопасности.
- `unknown` остаётся отдельным состоянием и в карточке объясняется отдельно от низкого риска.
- Признак — это совпадение формулировки. Он не доказывает мошенничество.
- «Оплата прошла» и «это не пароль» больше не помечаются как просьба перевести деньги или сообщить пароль.
- «Код из SMS оставляйте при себе» остаётся предупреждением, а не запросом кода.
- Казахский и смешанный текст с казахскими буквами по-прежнему получают `risk_level: unknown` и `language_evaluation: not_evaluated`.
- Если Vision уже стёр казахские буквы, модель видит только оставшуюся строку. Поэтому казахский снимок нельзя считать проверенным антифродом даже после удачного OCR.

## Фактические проверки

Backend: `pytest`, 48 тестов, все прошли. В них входят русский мошеннический текст, бытовой текст, предупреждение, казахский и смешанный снимки, пустой снимок, размытый снимок, GIF, файл больше 8 МБ, повреждённый PNG, рисунок без текста, две строки и скрытый комментарий PNG.

Frontend: `vitest run`, 6 тестов, все прошли. Отдельный тест проверяет, что распознанный текст показывается до карточки модели и что карточка получает ответ существующего текстового API.

Полный проход в браузере 22 ноября 2026, страница `http://127.0.0.1:5174/screenshot`. В поле файла передан нарисованный PNG с фразой «Служба банка: срочно переведите деньги на карту». Распознавание вернуло эту строку без дописывания. Проверка текста дала высокий предполагаемый риск модели `tfidf-linearsvm-0001m`, без процента. Признаки совпали с просьбой, срочностью и упоминанием банка. Блок «Распознавание» и блок «Оценка модели» показаны раздельно. Журнал API записал только путь и статус `200`. В `analysis_records` осталось 0 строк. Казахский переключатель перевёл страницу и карточку результата. На ширине 390 пикселей поле файла, текст и кнопка проверки остались доступны.
