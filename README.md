# SenimRadar AI

Платформа цифрового доверия: «Проверь, прежде чем доверять».

Сейчас готовы **этап 1**, экспериментальная модель **этапа 2**, сравнение **этапа 2.1**, локальное распознавание скриншота **этапа 3** и защита языка **этапа 3.1**. Казахский текст на снимке читает локальный Tesseract `kaz+rus`. Антифрод для казахского по-прежнему не выдаётся. Активная модель выбирается отдельным файлом и не затирает `tfidf-logreg-0001`. Процент не показывается. Казахский и английский вердикт пользователю не выдаются. Подробности в [docs/stage-2.md](docs/stage-2.md), [docs/stage-2-1.md](docs/stage-2-1.md) и [docs/stage-3.md](docs/stage-3.md).

## Что уже работает

- Backend на FastAPI: проверка живости, готовность базы, список возможностей и проверка текста.
- Запрос текста проверяется по длине и языку. Содержимое не сохраняется и не пишется в журнал.
- Если модель не настроена, ответ содержит `status: unavailable`, а `risk_level` и `risk_score` остаются пустыми.
- Интерфейс на React: обзор, сканер, разбор скриншота, заготовки следующих разделов, русский и казахский языки.
- Скриншот PNG, JPEG или WEBP читается локально через Apple Vision. Текст можно исправить и отправить в ту же модель. Файл не сохраняется.
- Схема MySQL и миграция Alembic. Исходный текст, скриншот и запись в таблицах не предусмотрены.
- История проверок выключена.

## Что ещё не работает

- Классификация мошенничества в тексте на живом трафике. Этап 2.1 улучшил русский синтетический тест, но не заменил его живыми сообщениями. См. [docs/stage-2-1.md](docs/stage-2-1.md).
- Казахский текст на скриншоте. Apple Vision его не поддерживает и может подменить буквы. Это не казахский антифрод. См. [docs/stage-3.md](docs/stage-3.md).
- Разбор ссылок без их открытия — этап 4.
- Объяснения на данных реальной модели — этап 5.
- Голос — этап 6.
- Учётные записи и история с согласием — этап 7.

## Окружение

Проверено на этом Mac:

- macOS 15.5, Apple Silicon
- Python 3.13.0
- Node.js 25.2.1 и npm 11.6.2
- MySQL Community Server 9.4.0 слушает `127.0.0.1:3306`. Это сервер, а не только MySQL Workbench
- База проекта называется `senimradar_ai`, кодировка `utf8mb4`
- Docker не установлен и для MySQL не нужен
- Порт 5173 уже занят другим локальным Vite. Если порт занят, Vite откроет 5174. Оба адреса разрешены в CORS.

PostgreSQL для проекта не используется и из этого этапа не устанавливается.

## Первый запуск

Из каталога `senimradar-ai`:

```bash
python3 -m venv backend/.venv
source backend/.venv/bin/activate
pip install -r backend/requirements.txt
```

```bash
cd frontend
npm install
```

Два терминала:

```bash
source backend/.venv/bin/activate
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
cd frontend
npm run dev
```

Интерфейс по умолчанию: <http://127.0.0.1:5173>. На этой машине порт 5173 занят, поэтому сейчас Vite открыт на <http://127.0.0.1:5174>.

Проверка API: <http://127.0.0.1:8000/api/v1/health>

Описание API: <http://127.0.0.1:8000/docs>

Те же команды запуска лежат в `scripts/dev-backend.sh` и `scripts/dev-frontend.sh`.

## База данных

API поднимается и без базы. В этом случае `/api/v1/health` отвечает `200`, а `/api/v1/health/ready` — `503` с `database: unavailable`.

Локальный MySQL уже запущен. Подготовка только базы `senimradar_ai` и отдельного пользователя описана в [docs/setup-macos.md](docs/setup-macos.md). Пароль приложения хранится в `backend/.env` и в репозиторий не входит.

## Конфиденциальность на этом этапе

- Текст уходит на локальный API, проверяется и отбрасывается.
- Внешний AI-провайдер не подключён. Ключей в репозитории нет.
- Скриншот остаётся в памяти на время распознавания и не записывается в базу или журнал.
- Подозрительные ссылки не открываются: поле адреса выключено. Ссылки, найденные на снимке, тоже не открываются.
- Журнал пишет тип ошибки и путь, но не тело запроса.
